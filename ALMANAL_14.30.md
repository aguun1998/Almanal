# 6.1 REPRESENTATION RACE / BOUNDED SEARCH CLOSURE

Before implementation, race a few **representations**, not many coded variants. Defaults:

```text
max_representation_hypotheses = 4
active_representation_beam    = 2
reserve_reopen_batches        = 1
ordinary_finalization_passes  = 1
```

Each record carries `mechanism + explicit feasibility + mandatory obligations + proof path + optimistic frozen-axis footprint + reasoning-work bound`; missing mechanism/feasibility/reasoning bound or an empty mandatory-obligation set is invalid. The footprint is estimated **before implementation** over task-relevant structural work, live memory/state, source/artifact complexity, and I/O when material; an empty/unknown footprint cannot win a static race merely by being unspecified. Apply feasibility/protected-floor/Pareto/pairwise dominance first; deepen only the active beam and keep other survivors reserve-only.

Prefer **proof-obligation bundles**: one invariant/representation that jointly closes necessity, sufficiency, construction/decision, and complexity obligations outranks separately reopening those obligations when the protected floors are equal. Then prefer lower-bound match and lower bounded reasoning work **for scheduling only**: `SchedulingPriority != EvidenceWeight != GlobalOptimalityProof`. Candidate-vs-candidate optimistic bounds or self-declared obligation metadata may rank the bounded beam but cannot eliminate an unwitnessed peer; static rejection requires a proved external frontier bound or a witnessed lock survivor. A survivor that closes mandatory obligations and matches the known lower bound/Pareto target becomes `RepresentationLock` only after host/runtime validation of that closure/bound evidence; an unvalidated cheaper lock claim cannot prune a validated lock candidate. Lock only when exactly one witnessed non-dominated lock survivor remains; multiple witnessed Pareto tradeoffs preserve the frontier rather than scalarize by scheduling cost/id. Stop opening families only after that witnessed transition. Reopen and post-lock falsification require a **fresh, validated, unconsumed** active-failure/counterexample/frontier witness. After lock, finalize once; another finalization pass likewise needs fresh validated evidence. A run-scoped serialized witness ledger makes validation+consumption one-shot even under concurrent callers; reusing the same witness cannot refresh a lease. The same ledger owns bounded ordinary-finalization/reserve budgets, so repeating caller counters cannot reopen work. `MoreThought != MoreQuality`.

When a strong structural claim is still uncertain, prefer a **cheap falsifier** only if one counterexample would reject or materially demote the candidate and the bounded falsification work is cheaper than another deep proof/search batch. Small exhaustive/random/property tests are counterexample searches by default: `NoCounterexampleFound != Proof` unless the tested domain is itself exhaustive for the claim. Experiments are not candidate generators and are not repeated after a representation lock without a fresh validated defect/frontier witness.

For algorithm/code artifacts, the default practical contract is: **semantic correctness + constraint/stability compliance are protected floors; then minimize a non-scalarized Pareto vector led by execution time, peak live memory, source/code bytes, and produced-artifact bytes**, unless the user/task freezes different priorities. # 6.3 PORTABLE EXECUTION-SHAPE CLOSURE

When runtime/memory/throughput/resource efficiency is a material task axis, inspect the verified simplified computation graph before considering backend-specific tuning. Use the least-complexity profitable rung:

```text
semantic representation
-> eliminate unnecessary materialization/state
-> single-pass / streaming form
-> safe in-place reuse / buffer lifetime shortening
-> locality-friendly layout / batchable independent work
-> portable data-parallel or branch-reduction opportunity when cheap
-> machine-specific intrinsics/pragmas/syscalls only by explicit high-performance admission
```

`StructureBeforeMicroarchitecture`. A specialized optimization is not an improvement merely because it may be faster on one machine. It must preserve correctness/protected portability constraints and repay added source/dependency/architecture/lifecycle complexity with task-relevant measured or otherwise claim-matched evidence. If the performance axis is not material, or the expected gain cannot change selection enough to repay complexity rent, STOP at the simpler portable rung.

This closure seeks execution-shape opportunities, not mandatory SIMD. Examples include replacing stored position vectors with a streaming prefix recurrence, reusing an input buffer after its lifetime ends, avoiding redundant passes/materialization, and exposing independent batch structure. Hardware-specific vectorization remains optional COLD/WARM technique, never a resident default.

# 6.4 ANALYTIC PARETO PRE-SCREEN / BENCHMARK-LAST

For optimization tasks, Pareto axes are frozen **before** variant generation. Correctness/protected validity is a hard floor. For practical algorithm/code tasks, unless overridden, the primary cost frontier is `exact_runtime(if witnessed) / structural_execution_work`, `peak_live_memory`, `source_bytes`, and `produced_artifact_bytes`; secondary structural axes such as passes, allocations, memory accesses, state count, materializations, and dependency/portability burden remain separate rather than silently scalarized.

```text
transformation hypothesis
-> semantic equivalence / feasibility obligation
-> analytic delta: asymptotic work, state count, live bytes, passes, materialization, exact source/artifact size when available
-> optimistic bound against current frontier
-> STATIC REJECT if infeasible, provably dominated, or unable even at its optimistic bound to improve the frontier
-> materialize only surviving frontier candidates
-> measure deterministic/exact axes without runtime benchmark
-> empirical benchmark only if an environment-dependent axis remains decision-relevant and its outcome can change selection
```

`Benchmark != DefaultVerifier`. Do not benchmark every generated variant. A benchmark has positive decision value only when static reasoning cannot settle the relevant Pareto relation and a plausible measurement outcome can alter the final choice. Repeated runs are admitted only when noise/uncertainty overlaps a precommitted material threshold; otherwise one paired decision batch is sufficient.

`StructuralEvidence != FabricatedTiming`: exact/proved operation/state/pass/allocation/materialization counts are valid structural execution-cost evidence and can establish that a candidate performs less modeled work. They do not by themselves assert an exact wall-clock number or guaranteed speed ratio. Cache/locality arguments without a proved model remain hypotheses. Exact source/artifact bytes and statically proven live-memory bounds require no runtime benchmark to be accepted on those exact axes.

Prefer **multi-axis structural moves** before micro-tuning: eliminate a state dimension, restrict useful states, shorten lifetimes, remove a pass/materialization, reuse storage, or collapse equivalent work. Candidate generation should seek transformations likely to improve several frozen axes simultaneously rather than independently polishing each metric after code exists.

For goal-specific DP/search/counting, inspect both directions before enumerating state:

```text
UsefulState = ForwardReachable ∩ BackwardCoReachable(Target)
```

If only one target is requested, do not compute all intermediate targets merely because a forward recurrence permits it. Goal-conditioned feasibility pruning is a static optimization and should precede benchmarking.
